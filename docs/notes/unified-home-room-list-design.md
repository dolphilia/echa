# トップページとルーム一覧の統合方針

記録日: 2026-07-26  
状態: 採用・v2 モックアップへ反映済み

## 結論

トップページとルーム一覧は分離せず、ルーム一覧をサービスのホーム画面として扱う。

大きなヒーロー、機能紹介、繰り返しの CTA をページ上部に置く LP 型の構成は採用しない。ユーザーがページを開いたら、現在のサービス状況と開催中のルームをすぐに確認できる構成にする。

非ログイン時とログイン後で別ページを作るのではなく、同じ情報設計の中で必要なセクションと操作だけを切り替える。

## 背景

以前のモックアップは、次の 2 ページに分かれていた。

- `prototypes/v2/landing/index.html`
  - 大きなヒーロー
  - お絵描きルームの紹介画像
  - 機能紹介
  - 使い方
  - 複数の CTA
- `prototypes/v2/rooms/index.html`
  - 開催中のルーム一覧
  - 検索・フィルター
  - ルーム作成

この構成には次の問題があった。

- 実際のルームへ到達するまでに 1 ページ余分に経由する。
- サービスの主目的より、サービス紹介の比重が大きく見える。
- トップページとルーム一覧の両方で、開催中のルーム数や参加への CTA を重複して表示している。
- トップページは「登録なしで参加できる」と説明している一方、ルーム一覧は通知、アバター、ルーム作成などログイン済み前提の表示になっている。
- ページごとにヘッダーのナビゲーションやログイン状態の前提が異なる。

## 統合後の情報設計

ページ上部から次の順序で表示する。

1. 共通ヘッダー
2. コンパクトなホーム導入
3. ログイン後のみ「参加中・最近見たルーム」
4. 開催中のルーム一覧
5. 非ログイン時のみ簡潔な利用案内
6. フッター

### 共通ヘッダー

- ロゴのリンク先は統合ホームにする。
- 主ナビゲーションは「ルーム」「ギャラリー」「ヘルプ」とする。
- ページ内アンカーの「機能」「使い方」は廃止する。
- 非ログイン時は「ログイン」「アカウントを作る」を表示する。
- ログイン後は通知とアバターを表示する。

### コンパクトなホーム導入

大きなキャッチコピーや装飾画像は置かない。

非ログイン時の見出しは「ルームを探す」とし、次の情報だけを簡潔に伝える。

- 現在のルーム数と参加人数
- 公開ルームは登録なしでも参加できること
- ゲスト参加ではニックネームを設定すること

ログイン後は、ユーザーへの短い挨拶と「ルームを作る」操作を表示する。

### 参加中・最近見たルーム

ログイン後だけ表示する。

- 現在参加中のルーム
- 最近閲覧したルーム
- 前回の続きへ戻る操作

開催中のルーム一覧より上に置き、復帰操作を最短にする。

### 開催中のルーム一覧

統合ホームの中心となるセクション。

- ルームカード
- 参加人数
- 観覧者数
- 開催状態
- お題
- タグ
- 検索
- フィルター
- 並び替え

カードの操作ラベルは状態に応じて切り替える。

| 状態 | 操作 |
| --- | --- |
| 非ログイン・参加可能 | ゲスト参加 |
| ログイン済み・参加可能 | 参加する |
| 参加中 | ルームに戻る |
| 満員・観覧可能 | 観覧する |
| 開始前 | 参加する、または開始を待つ |

### 非ログイン時の利用案内

機能紹介を完全に削除するのではなく、ルーム一覧の後ろへ小さく配置する。

案内する内容は次の 3 点に絞る。

1. ルームを選ぶ
2. ニックネームを決める
3. 描きながらチャットする

ページ上部ではなく一覧の後ろへ置くことで、LP 感を抑えながら初見ユーザーへの説明を残す。

## ログイン状態による差分

| 項目 | 非ログイン | ログイン後 |
| --- | --- | --- |
| ヘッダー右側 | ログイン、アカウント作成 | 通知、アバター |
| ホーム導入 | 登録不要の案内 | 挨拶、ルーム作成 |
| 参加中・履歴 | 表示しない | 表示する |
| ルーム作成 | 表示しない、またはログインへ誘導 | 作成モーダルを開く |
| 公開ルームへの参加 | ニックネームとカラーを設定 | そのまま参加 |
| フィルター | すべて、参加可能、観覧可能 | 左記に加えてフレンド |
| ページ下部の説明 | 表示する | 表示しない |

## ゲストとアカウントの役割

「アカウント登録なしで参加できる」という方針は維持する。

### ゲストで可能にする操作

- 公開ルームの閲覧
- 観覧可能ルームの観覧
- ニックネームと参加カラーを設定した公開ルームへの参加
- 描画とチャット

### ログインを必要とする候補

- ルーム作成
- 参加履歴の保存
- 最近見たルームの同期
- フレンド機能
- プロフィール
- 通知
- 作品や設定の永続化

ゲスト参加の気軽さを残しつつ、継続利用や所有を伴う機能をアカウントの価値にする。

## URL 方針

本番実装では、統合ホームを `/` に置くのが第一候補。

- `/`: 統合ホーム
- `/rooms/`: `/` と同じ画面、または `/` へ転送
- `/landing/`: 廃止。紹介ページが必要なら `/about/` として別途用意

v2 モックアップでは次の構成とする。

- `prototypes/v2/rooms/index.html`
  - 統合ホームの本体
  - 初期状態は非ログイン
- `prototypes/v2/rooms/?auth=user`
  - ログイン後状態の確認用
- `prototypes/v2/landing/index.html`
  - クエリとアンカーを維持して `rooms` へ転送

## モックアップで実装した内容

- 非ログイン／ログイン後を 1 ファイル内で切り替える構成
- 非ログイン時のゲスト参加モーダル
- ログイン後の参加中・最近見たルーム
- ログイン後のルーム作成モーダル
- 状態に応じたヘッダーとフィルター
- 状態に応じたカードの参加ラベル
- 閉じたモーダルの `aria-hidden` と `inert`
- 狭い画面向けのヘッダー、フィルター、カードのレスポンシブ調整
- 旧トップページから統合ホームへの転送

## 今後の実装で決めること

- 本番ルートを `/` と `/rooms/` のどちらに統一するか。
- ゲスト参加情報を Cookie、Session Storage、Local Storage のどこに保存するか。
- ゲストがルーム作成できるか、作成にはログインを必須にするか。
- 「参加中」と「最近見た」の保存期間。
- フィルター、検索、並び替えの API 仕様。
- 満員ルーム、開始前ルーム、招待限定ルームの操作ラベル。
- ログイン後にルーム一覧より優先して表示する情報の上限。
- 紹介専用ページ `/about/` が本当に必要か。

## 実装上の注意

- 認証状態によってページ全体を別コンポーネントにせず、共通のルーム一覧とカードを再利用する。
- ログイン状態はサーバー側で確定し、初期 HTML から正しい要素を出し分けて表示のちらつきを防ぐ。
- 非ログインでも公開ルーム一覧は同じ API から取得できるようにする。
- ゲスト参加モーダルとログイン後の参加処理は、最終的に同じ入室 API へ収束させる。
- LP 的な情報を追加する場合も、開催中のルーム一覧より上へ大きく配置しない。
